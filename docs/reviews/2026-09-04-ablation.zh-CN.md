# 核心抽象消融评审 — 2026-09-04

[English](./2026-09-04-ablation.md)

## 决策

两层安装转发可以考虑移除：`Install-WinGetPackage` 和 `Install-ScoopPackage` 各自只供对应 Provider 入口调用。将函数体移到该入口，可减少两个函数、十行代码，不改变 Provider 契约。实验变体保留了已观察到的行为。

保留 Provider 注册校验、mise 上下文适配和包定义复制。移除这些设计后，出现了具体的契约或 Profile 错误。单独的配置深拷贝是否必要仍无定论：实验确认了对象别名问题，但没有证明用户可见的回归。

这是工程评审记录，不是新的架构 RFC，也不表示整个项目已经完成优化。没有将实验中的运行时代码删减合入主线。有价值的错误案例已保留在现有[架构测试](../../scripts/test-architecture.ps1)中；没有新增常驻消融框架、依赖或 CI 任务。运行时精简落地前，仍需完成受支持 Windows 环境的验证。

## 方法

- 基线为提交 `b000ee2`，包含已经批准的助手规范；运行时代码与 `c8f40c5` 相同。
- 环境为 Linux x64、PowerShell 7.6.5；每轮使用新进程和隔离的临时状态。新增检查模拟原生命令调用，现有测试使用 mock 和 dry-run。这些测试没有安装或卸载用户实际使用的软件。
- 每个源码副本只改一个因素，不叠加变体。第一阶段保持原测试不变。
- 每个副本运行 `pwsh -NoProfile -File ./scripts/test.ps1`，另加 17 项检查：4 项 WinGet/Scoop 安装参数、2 项原生命令错误传播、3 项 mise 上下文、6 项非法注册、Profile 重复组合，以及 1 项配置对象别名检查。
- 共完成 6 轮基线/变体测试和 102 次补充检查。结果是功能观察，不是性能基准，也不能证明未覆盖场景的等价性。

### 为什么不能只看原测试是否通过

移除注册校验后，正常搜索、安装和移除派发仍可运行，因此原测试通过。但错误注入证明：未知 Provider、重复注册、空操作表、未知操作、不存在的 handler，以及没有实现的 owner 都会被接受。这些校验用于发现内部契约错误；本实验不声称存在外部插件漏洞。

删除 mise 适配器后，原测试也通过。但直接传入 `ProfileManagedMise = $true` 调用 handler，捕获的原生命令参数从 `install node@26` 变成了 `use --global node@26`。这是真实的归属与配置差异，不只是 helper 改名。

包定义复制并非只是多调用一次函数。失去字段筛选和独立结果对象后，原有纳入测试在 `/packages/0/_identity` 处违反 schema。复用同一 Profile override 时也会校验失败，因为 `_identity`、`_refs`、`_claims`、`_defaultSelected`、`_profileGroups` 和 `_runtime` 已经被加入输入对象。

配置深拷贝检查的证据较弱：它修改候选配置的嵌套属性，然后观察原对象是否改变。不复制的实现必然失败。由于受测命令仍通过，这本身**不能证明**真实用户流程需要深拷贝。不要把这类检查升级成禁止未来合理重构的测试。暂时保留现有一行复制逻辑，待专门检查调用点及回滚需求；本次没有测得性能收益。

## 保留的回归检查

架构测试新增了 16 个行为/契约场景，不要求保留两层转发 helper 的名字，也不限定配置复制的具体实现。刻意没有保留仅验证对象别名的检查。

强化后的测试已针对六个副本分别运行：

- 基线和删除纯转发的变体通过。
- 删除注册校验、丢失 mise 上下文及缺少包定义复制的变体，均因预期原因失败。
- 删除配置深拷贝仍通过，反映其命令级必要性尚无结论。

这样可以区分真正有价值的测试，与仅仅把当前实现固定下来的断言。

## 复现与后续评估

1. 在 `b000ee2` 创建隔离的源码副本，不修改已经安装的 Winenv 目录或真实包管理器配置。
2. 每个副本只应用表中一项改动，同时保留不修改的对照组。
3. 在各副本中运行基线版本的 `scripts/test.ps1`。
4. 将本次评审强化后的 `scripts/test-architecture.ps1` 复制到各副本并重跑。未修改的生产运行时必须先通过。
5. 研究配置复制时，可比较修改 `Copy-WinenvConfig` 返回值的嵌套属性是否影响原配置，再追查实际命令、取消、重试或回滚的后果。仅有对象别名断言不够。
6. 接受运行时精简前，须在受支持的 Windows 上运行完整检查，包括 `powershell.exe -NoProfile -File ./scripts/test-windows-powershell.ps1`，并审查来源限定、错误传播、Profile 归属和发布打包。

本次 Linux 实验没有验证 Windows 集成和 Windows PowerShell 5.1。其他模块、文档基础设施及发布自动化仅用于理解上下文，未进行消融。经过校验的注册表和轻量入口仍是已接受的架构。
