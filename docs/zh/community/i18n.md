# 翻译指南

Winenv 的 CLI、安装器、仓库入口和文档完整支持英文（`en-US`）与简体中文（`zh-CN`）。

## 权威来源

英文是权威版本，位置包括：

- `win.ps1` 和 `install.ps1` 中的英文源码消息；
- `docs/` 根目录下的英文页面；
- `CONTRIBUTING.md` 等根目录仓库规范。

简体中文位于：

- CLI 使用的 `locales/zh-CN.json`；
- 文档站使用的 `docs/zh/`；
- 带 `.zh-CN.md` 后缀的规范和 README 对照文件。

英文资源文件用于说明 locale 结构；因为源码消息已经是英文，其中的映射保持为空。

## 运行时语言选择

CLI 和安装器按以下优先级解析语言：

1. 明确传入的 `-Lang` 或 `-Language`；
2. `WINENV_LANG` 环境变量；
3. `%LOCALAPPDATA%\Winenv\config.json` 中持久保存的 `language`；
4. Windows 当前 UI culture（`zh-*` 使用中文，其余使用英文）。

显式传入 `auto` 会在这一次执行中跳过环境变量和持久偏好，直接查询系统 UI 语言；`win lang auto` 会持久保存这种行为。

文档英文位于 `/`，中文位于 `/zh/`。首次访问时按浏览器语言选择；通过语言菜单手动切换后会在本地保存，并在以后优先使用。

## 翻译规则

- 命令名、参数、路径、环境变量、包 ID、代码、JSON key 和日志片段保持原样。
- 用户文字优先保证自然、准确，不强求逐字对应。
- WinGet、Scoop、mise、Profile、manifest、bucket、Release、Issue、Pull Request 等术语通常保留，方便跨页面检索。
- 统一表达核心语义：`adopt` 是在不重装的情况下增加可复现声明；`reuse` 是已有兼容安装满足计划；`unclaimed` 不等于已经卸载。
- 不得超出英文原文承诺安全性、支持范围或兼容性。
- 中文页面的站内链接通常留在 `/zh/`，英文页面留在根语言。

## 新增或修改消息

英文 CLI 消息同时是后备 key。固定消息使用 exact 映射，动态消息使用范围明确且带起止锚点的正则；只有短语不会误伤包名和上游输出时才使用 replacement。

修改用户可见内容后运行：

```powershell
pwsh -NoProfile -File ./scripts/test-i18n.ps1
pwsh -NoProfile -File ./scripts/test.ps1
npm run docs:build
```

国际化测试会验证资源 JSON、语言优先级、持久化、系统语言自动检测、表格输出，以及 CLI 的终端输出必须经过翻译包装层。

## 增加其他语言

新增语言不只是添加一个 JSON。它需要长期维护 CLI 资源、安装器消息、完整文档、VitePress 导航和搜索文字、浏览器路由、自动测试，还需要能持续评审的贡献者。实现前应先创建设计 Issue，明确长期维护者。
