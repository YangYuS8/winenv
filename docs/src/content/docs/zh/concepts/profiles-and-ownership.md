Profile 描述期望的环境。它既不是包管理器数据库的副本，也不是自动卸载清单。

## 三个不同的问题

| 问题 | 答案来自 |
| --- | --- |
| 这个环境应该包含什么？ | 当前启用的 Profile 声明 |
| 电脑上实际安装了什么？ | 管理器清单和 Windows 安装记录 |
| 谁负责更新或卸载这份安装？ | 实际管理器或原始厂商安装途径 |

`win diff` 对比前两项，不会因为名称熟悉就猜测归属，也不会因为某个软件没有被 Profile 声明就把它删除。

## 共享 Profile 增加的是独立声明

导入别人的 Profile 会保存独立快照，不会覆盖个人配置层。两条相同声明保留各自引用，但只要求一份安装。不兼容的版本或相互竞争的命令提供者，需要明确的本地选择。

停用共享 Profile 只移除它的活动声明。其他层仍引用的软件继续保留引用；不再被任何层引用的软件变为 `unclaimed`，但仍安装在电脑上，并由原来的途径管理。卸载始终是另外一个需要明确执行的操作。

## 复用不等于纳入

复用表示已有兼容安装满足需求；纳入则是为选定的已有软件记录可复现声明。两者都不需要把软件说成是 Winenv 最初安装的。

未知的 EXE/MSI 安装可能只能作为 Windows 记录展示。Winenv 不会编造包标识，也不会承诺能够重现它们。

具体操作见[组合 Profile](/winenv/zh/guide/profiles/)，旧电脑接入见[纳入已有安装](/winenv/zh/guide/existing-windows/)，存储细节见[状态与安全](/winenv/zh/reference/state-and-security/)。
