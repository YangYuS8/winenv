Winenv is an opinionated management layer for software and development environments on Windows 11. It does not create a fourth package repository. Instead, it gives WinGet, Scoop, and mise clear responsibilities behind short commands, live search, composable profiles, and reproducible installation plans.

Read the guides, command reference, and automatically synchronized release history on the **[Winenv documentation site](https://yangyus8.top/winenv/)**.

## Install

Run this in a regular PowerShell window:

```powershell
irm https://raw.githubusercontent.com/YangYuS8/winenv/main/install.ps1 | iex
```

The installer downloads the latest stable [GitHub Release](https://github.com/YangYuS8/winenv/releases/latest), verifies SHA-256, creates the global `win` command, and reuses compatible prerequisites already installed on the machine.

Start here:

```powershell
win                 # open the interactive software picker
win vscode          # search for and install software
win diff            # compare active profile declarations with this PC
win scan            # inventory the current PC without changing it
win check           # inspect managers and conflicts
win help            # show compact help
```

English is the default source language. Winenv automatically follows a Chinese Windows UI culture and can be changed at any time with `win lang en`, `win lang zh`, or `win lang auto`.

See [Getting started](https://yangyus8.top/winenv/guide/getting-started) for installation options.

## Design principles

- WinGet owns applications that need Windows integration, Scoop owns portable CLIs, and mise owns development runtimes that need version switching.
- Search queries live manager catalogs. Winenv does not maintain a stale package index or silently guess between competing sources.
- The built-in profile contains only Winenv runtime requirements. Personal and community profiles remain independent and composable.
- Existing PCs can scan and selectively adopt installed software; reinstalling Windows is not required.
- Versions, release notes, checksummed assets, and the documentation site are generated by GitHub Actions.
- The stable entry point loads independently tested internal modules through a validated provider contract. See [RFC 0001](https://yangyus8.top/winenv/reference/architecture).

```powershell
npm ci

```
